# Surge Ad Check

按需检查微博、直播吧、闲鱼：连接 iPhone 观察过滤前后的脱敏统计，或导入 HAR 做本地模拟，再与确认过的基准对比。Rust 后端、原生窗口和界面打包在同一应用内，使用者无需安装 Rust、Node 或 Python。

## 使用

1. 打开 Mac 应用，直接进入独立窗口，通过“检测／报告／过滤原理／设置”切换功能，不会打开浏览器。可将应用拖入“应用程序”文件夹；重复打开会激活已有窗口。
2. 实时检测：手机和 Mac 接入同一局域网，在手机 Surge 中启用远程控制。Mac 安装 Surge，并通过 iCloud 同步相应配置。选择本机配置文件，填写手机局域网地址，点击“保存并检查连接”。工具读取已有 `external-controller-access`，不会代写主配置。USB 和 iPhone 镜像本身不提供此控制通道。
3. 点击“开始检测”。首次使用工具会在 Surge iCloud 目录写入独立的 `SurgeAdCheck.sgmodule` 和三个观察脚本；打开 iPhone Surge 等待同步，然后重试开始。
4. 按界面的路线打开三个应用，确认首页、搜索、评论、图片、视频或商品详情正常。点击“结束并生成报告”。最长 6 分钟；界面停止心跳 45 秒后也会尝试结束。
5. 填写目测结果。只有实机采集且无诊断异常、你确认未见广告并且浏览正常的接口才允许设为基准。以后按相同路线检查，差异会标为“需要复查”。

首次启动可能出现 macOS 的开发者验证提示。本项目的本地构建使用临时签名，未经过 Apple 公证；仅对确认来源的下载，在系统设置的“隐私与安全性”中允许打开，不需要关闭系统整体安全检查。

实时检测依赖三个已安装模块的固定脚本版本及匹配顺序。若版本或重叠脚本不符合预期，启动会失败并尝试关闭诊断模块；更新工具或核对模块后再试。工具不会为了连接方便自行修改 Home。模块在手机上的下载缓存还需由 Surge 正常管理。

## 界面与操作

- **检测**：连接、浏览、看报告三步，显示各应用的检查路线和采集覆盖；未配置时主按钮直接带到连接设置。
- **报告**：先显示结论和证据缺口，默认优先展示需要复查的位置；可切换全部、未采集、已采样。展开查看原因、广告标记统计和正常字段校验范围。正文无法识别时显示“待判断”，不会把缺失计数当作 0 条广告。
- **过滤原理**：用明确标注的演示数据解释响应清理、请求拦截与效果核验，可切换处理前后；演示不是实际检测结果。
- **设置**：手机连接、可选模型 API、诊断恢复。模型分析入口在报告页，支持先预览发送摘要。

检测进行时禁用连接修改和 HAR 导入，结束后自动打开报告。未保存的输入和已展开的证据不会被定时刷新覆盖。界面中的新地址、结构变化和目测异常仍然只是需要复查的依据，不会触发自动修改过滤规则。

## 结果是什么意思

- **未覆盖**：没有该位置的有效采样，不能判断过滤有效。
- **已观察、无基准**：有采样，已知检查未发现异常；尚未和确认过的基准比较。
- **与基准一致**：本次采样符合已知检查和结构基准，不代表所有广告均被删除。
- **需要复查**：有残留已知广告标记、正常字段变化、格式异常、结构/内容类型变化、错误响应或模拟数据等线索。

只识别已有过滤器了解的广告标记。未知广告可能没有可识别字段；结构和类型变化也可能来自正常内容。微博正文仅做已知标记统计及翻页字段校验，不能据此证明所有正常内容均保留。直播吧的拒绝请求数是线索，不能证明屏幕呈现。开屏缓存、A/B 测试和未浏览页面都可能造成遗漏。

实机摘要仅保留结构指纹及类型统计；HAR 模拟还包含脱敏字段路径和类型，不含字段值，未知字段名被指纹化。短日志片段重组失败会报告证据缺口。指纹用于比较，**不是加密或匿名性保证**。结构采样有大小、深度和数量限制，超限不会误报通过。

## HAR 与手机抓取数据

可将 Surge 导出的 HAR（含响应正文）通过 AirDrop / 文件同步传到 Mac，再点击“导入 HAR”。正文只在本机内存中解析，不复制到报告，也不发送给模型。工具用内嵌的可信过滤代码对捕获正文做模拟回放。若 HAR 正文已经是过滤后的内容，无法还原原始广告；模拟不能证明手机实际上执行了同一过滤器，也不能设为实机基准。没有正文、非 JSON、未知接口或未解密 HTTPS 会明确留下证据缺口。

## 可选模型分析

默认关闭，仅在点击“测试连接”或“发送本次摘要并分析”时调用；没有定时调用。

- Qwen 默认 Base URL：`https://dashscope.aliyuncs.com/compatible-mode/v1`，模型 `qwen-plus`。不同地区/工作空间应按阿里云控制台提供的地址与模型修改。
- DeepSeek 默认 Base URL：`https://api.deepseek.com`，模型 `deepseek-flash`。以账号可用模型为准，可自行填写其他 ID。
- 其他支持非流式 Chat Completions 的 HTTPS 服务可自定义。地址不包含 `/chat/completions`。提供商和模型会变化，连接测试会反馈鉴权、模型、限额或响应格式错误。

密钥只保存到当前 Mac 的钥匙串，不跨机器同步，不进入 JSON 配置、报告或交接包。每个 Base URL 分开保存密钥。测试只发送要求回复 OK 的短消息；分析发送界面可预览的脱敏诊断摘要，按所用 API 计费。最大输出 256–2400 tokens，50 秒超时，不跟随重定向。选择服务商、地址和模型后点击“保存并测试”，会先保存当前填写内容，再测试连接。

LLM 适合梳理证据、解释可能原因、提出最小修改方向、补抓步骤与验证方案。摘要通常不足以直接编写未知接口的修复，因此本版不自动生成、执行或安装候选脚本；具体补丁由编程助手结合充分证据准备。模型文字属于未验证建议。未提供真实 API 密钥时，只能验证协议构造和本地错误处理，不能声称对应账号连接已通过。

## Codex / Claude Code 接手

点击“导出 Codex / Claude Code 交接包”，解压后让助手读取 TASK.md。包中有报告、版本与源代码 SHA-256、脱敏模型摘要和维护约束，不含原始 HAR、连接信息或密钥。项目的 AGENTS.md 和 CLAUDE.md 也记录了边界。

建议要求助手：“按交接包定位变化，证据不足先列出最小补抓范围；证据充分时生成候选补丁和回归测试，保留普通内容和翻页。不要修改 Home，不要安装未验证规则。”

## 安全恢复与本地数据

仅开启名为 `Surge Ad Check` 的独立模块，执行和原过滤器相同的内嵌代码，同时记录限时统计。它不新增 Rule、MITM 或 General 设置。开始前验证脚本匹配优先级，前后对 Home 文件做校验。

结束时关闭诊断模块，原模块保持原状态。独立保护进程在超时后继续尝试关闭；连接断开时无法保证远程关闭，但观察日志租约会过期，过滤逻辑保持原样。若界面提示恢复未完成，请在手机 Surge 手动关闭 `Surge Ad Check`，或连接恢复后点击“关闭诊断模块”。工具不会改写 Home 来修复状态。

本地设置、脱敏报告和恢复记录位于 `~/Library/Application Support/Surge Ad Check/`，目录权限为当前用户专用。文件不自动上传。应用通过本机随机端口服务界面，API 使用随机访问凭证并检查来源。关闭窗口、按 ⌘Q 或点击“退出工具”都会结束采集、尝试关闭独立诊断模块并停止本地服务。⌘, 打开设置，编辑菜单支持复制粘贴；导入和导出使用 macOS 文件选择／保存窗口。窗口内使用系统 WebKit，Rust 后端与界面同属一个应用进程；本机随机端口只在应用运行期间存在。

## 开发与打包

```sh
cargo test --locked --manifest-path tools/ad-check/Cargo.toml
cargo run --locked --manifest-path tools/ad-check/Cargo.toml
rustup target add aarch64-apple-darwin x86_64-apple-darwin
tools/ad-check/package-macos.sh /absolute/output-directory
```

依赖锁定在 Cargo.lock；Boa 执行内嵌过滤 JavaScript，HAR 从不作为代码运行。支持 `--data-dir PATH` 使用隔离测试目录，`--no-open` 仅供开发测试，运行无窗口服务；普通启动始终创建独立窗口。测试覆盖原过滤行为对照、日志故障、隐私字段排除、会话/版本匹配、模拟数据隔离和基准保留。更新过滤源后需重新编译工具。Apple Silicon 可在本机运行验证；Intel 构建是否实机验证应以对应发布说明为准。
